# 30天学习方案 — GPS实时定位追踪智能小车项目（new_gaijin版）

## 零、当前状态与使用说明（2026年9月更新）

> **请务必先读本节**，它决定了第 3~4 周的学习方式。

**仓库现状**：`new_gaijin/` 下的 8 个算法模块（ng_coord、ng_gps_parser、ng_json_builder、ng_timer、ng_error、ng_led_status、ng_mqtt_wrapper、ng_app）**已经全部实现**，其中前 3 个模块附有完整 PC 端测试（`test/` 目录，含可运行的 `test_all.exe`）。详见 `new_gaijin/README.md` 模块状态表。

**因此，第 3~4 周（Day15~27）采用"盲写后对照"模式**：

1. **盲写**：先不看 `src/ng_*.c` 参考代码，仅凭 `include/ng_*.h` 的接口声明和当天文档中的算法要点，在 **`new_gaijin/practice/dayNN/`** 目录下自己独立实现（这个目录由你自己创建，每天一个子目录）；
2. **对照**：完成后打开参考实现，逐个函数对比差异，思考"它为什么这样写"，记入当天文档的问题表；
3. **验证**：运行 `test/` 下的已有测试（把编译命令中的 `../src/ng_xxx.c` 换成你的 `../practice/dayNN/ng_xxx.c`），确认全部通过；第 4 周依赖硬件的模块改为 gcc 语法检查 + Keil 编译。

**铁律：不要修改 `src/`、`include/`、`adapter/` 下的参考实现**——它们是"标准答案"，改了就失去了对照的意义。

这样既保留了从零构建的深度训练，又能利用已有实现作为"标准答案"即时反馈，比单纯从零创建或单纯阅读效果都更好。

**与另一份学习计划的关系**：本项目还有一份 8 周版学习路线图（`learn/04-学习路线图.md`）。两者分工如下：
- **本 30 天计划 = 主线**：目标是接手并掌握 new_gaijin 模块体系；
- **8 周版 = 扩展参考**：其第 1~5 周与本计划第 1~2 周内容重叠（可任选其一阅读），**第 6~8 周（ESP8266 智能锁箱、树莓派串口通信、综合扩展）是本计划未覆盖的内容**，建议主线完成后按需补学。

## 一、学习目标总述

本学习计划专为**接手本项目的开发者**设计，帮助你在30天内从零开始全面掌握基于 **STM32F103ZET6 + BC20 4G模块** 的GPS实时定位追踪智能小车系统，并具备在 `new_gaijin/` 目录下构建高级算法模块的能力。

**完成本计划后，你将能够：**
- 理解原项目三层架构（执行层/传输层/应用层）和数据流
- 理解改进版的6个状态机、超时保护、配置集中化等改进成果
- 在PC端独立编写和测试核心算法模块（坐标转换、GPS解析、JSON构建）
- 在STM32上集成new_gaijin所有算法模块，并通过编译开关验证新旧代码共存
- 独立完成端到端系统测试和边界测试

## 三、每天预计学习时间与节奏规则

- **每天 2～3 小时**
- 建议分配：60% 阅读代码 + 30% 实践任务 + 10% 记录总结
- **总周期按 35 天规划**：30 个学习日 + 5 个机动缓冲日（P1~P5，见 `学习历程.md` 表尾）

**节奏规则**：

1. **每周最后半天为机动时间**：Day07 / Day14 / Day21 / Day28 的下午不排新任务，用于补欠账或复盘本周笔记；
2. **落后处理**：某天任务未完成可顺延，但**顺延累计超过 2 天**时，优先降级以下任务（跳过不影响主线理解）：
   - Day05 的"画时序图"可简化为看懂现有图；
   - Day11 / Day12 的 ESP8266、Python 脚本对比可只读结论部分；
   - Day24 的 LED 状态指示可只盲写框架、不实现全部 8 种闪烁模式；
3. **不可跳过**的硬性任务：Day16~20 三个核心算法模块的盲写与测试、Day26 编译开关验证——它们是后续天数的基础；
4. **连续 2 天卡壳**（同一问题超过 2 小时无进展）：记录到 `学习历程.md` 问题表，标记后继续往下走，用缓冲日回补。

## 七、学习方法建议

### 7.1 阅读代码的技巧
1. **从`main.c`入手**：先看主循环在做什么，再深入各个函数
2. **追踪数据流**：用彩色笔在纸上画出数据从输入到输出的完整路径
3. **先整体后局部**：先理解模块职责，再抠具体实现细节
4. **对比阅读**：同时打开原版和改进版，观察差异，理解"为什么要这样改"

### 7.2 实践任务执行
1. **不要跳过动手环节**：看懂代码≠能写出代码，必须亲手敲
2. **每次只改一处**：修改代码后先编译验证，再继续下一步
3. **善用调试工具**：串口助手、逻辑分析仪（如有）、Keil仿真器
4. **记录一切**：遇到的错误、解决的思路、关键的代码片段都要记录

### 7.3 笔记与总结
1. **每日打卡**：完成当天的 `dayXX.md`，填写自检清单
2. **画图比文字更有效**：状态机图、数据流图、时序图
3. **每周回顾**：周末花1小时回顾本周笔记，标注"不理解"的地方
4. **教别人是最好的学习**：尝试向同学讲解你今天学到的内容
