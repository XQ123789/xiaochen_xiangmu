# 01 - 硬件基础

本文介绍项目中使用的各硬件模块的基本原理和使用方法，帮助你快速理解"这些芯片是干什么的"。

---

## 一、STM32F103ZET6 核心外设

STM32F103ZET6 是本项目的主控芯片，基于 ARM Cortex-M3 内核，主频 72MHz，Flash 512KB，RAM 64KB。本项目主要使用了以下外设：

### 1.1 UART 串口通信（3 路）

| 串口 | 波特率 | 用途 | 关键函数 |
|------|--------|------|---------|
| UART1 | 115200 | 调试输出（printf 打印信息） | `uart_init()`, `Uart1_SendStr()` |
| UART2 | 115200 | BC20 4G 模块通信（AT 指令） | `uart2_init()`, `Uart2_SendStr()` |
| UART3 | 115200 | 树莓派通信（坐标下发） | `uart3_init()`, `Uart3_SendStr()` |

串口使用中断方式接收数据，数据存储在 `buf_uart2.buf` 等缓冲区中。初始化代码在 `SYSTEM/usart/usart.c` 中。

### 1.2 GPIO 通用输入输出

本项目使用的 GPIO 引脚：

| 引脚 | 功能 | 模式 |
|------|------|------|
| PA11 | DHT11 数据线 | 推挽输出 / 上拉输入（动态切换） |
| PA12 | 4G 模块开关控制（PWRKEY） | 推挽输出 |
| PB3 | LED3 | 推挽输出（低电平点亮） |
| PB4 | LED2 | 推挽输出（低电平点亮） |
| PB5 | LED1 | 推挽输出（低电平点亮） |

> 注意：PB3、PB4 默认被 JTAG 占用，代码中通过 `GPIO_PinRemapConfig(GPIO_Remap_SWJ_JTAGDisable, ENABLE)` 将其释放为普通 GPIO。

### 1.3 独立看门狗（IWDG）

看门狗的作用是防止程序跑飞。如果程序在指定时间内没有"喂狗"，芯片会自动复位。

```c
IWDG_Init(6, 500);  // 预分频64，重装值500
```

- 预分频系数 64，IWDG 时钟 = 40kHz / 64 = 625Hz
- 超时时间 = 500 / 625 = 0.8 秒（代码注释说约 4 秒，实际取决于 LSI 频率）
- 主循环中通过 `IWDG_Feed()` 喂狗，防止系统复位

### 1.4 定时器

定时器配置在 `HARDWARE/TIMER/timer.c` 中，用于产生精确的时间基准（如 PWM 控制电机等）。

## 二、BC20 / EC200U-CN 4G 模块

BC20 是移远通信的 4G Cat M1/NB-IoT 模块，本项目使用的 EC200U-CN 是移远的 4G LTE Cat 4 模块，两者 AT 指令集基本兼容。

### 2.1 核心功能
- **GPS 定位**：模块内置 GPS 接收器，通过 `AT+QGPS=1` 开启，`AT+QGPSLOC=2` 读取定位数据
- **4G 网络通信**：通过 SIM 卡接入移动网络，支持 TCP/UDP/MQTT/HTTP 等协议
- **MQTT 客户端**：模块内置 MQTT 协议栈，可直接连接 MQTT 服务器

### 2.2 关键 AT 指令

| AT 指令 | 功能 | 示例响应 |
|---------|------|---------|
| `ATE1` | 开启回显 | OK |
| `ATI` | 查询模块型号 | EC200U-CN |
| `AT+CIMI` | 读取 SIM 卡 IMSI | 46000... (460 开头表示中国移动) |
| `AT+CGATT?` | 查询网络附着状态 | +CGATT: 1 (已附着) |
| `AT+CSQ` | 查询信号质量 | +CSQ: 18,0 (值越大信号越好，31 为最强) |
| `AT+QGPS=1` | 开启 GPS | OK |
| `AT+QGPS?` | 查询 GPS 状态 | +QGPS: 1 (已定位) |
| `AT+QGPSLOC=2` | 读取 GPS 定位数据 | +QGPSLOC: 084235.0,... |
| `AT+QMTOPEN=0,"host",port` | 打开 MQTT 连接 | +QMTOPEN: 0,0 |
| `AT+QMTCONN=0,...` | MQTT 登录 | +QMTCONN: 0,0,0 |
| `AT+QMTPUBEX=0,...` | MQTT 发布数据 | > (提示发送) |

### 2.3 MQTT 连接参数

```
服务器: mqtts.heclouds.com
端口:   1883
产品ID: your_product_id
设备名: your_device_name
认证:   基于设备密钥的 Token（version=2018-10-31 签名）
```

## 三、ESP8266 WiFi 模块

ESP8266 是乐鑫的低成本 WiFi SoC，本项目用它做智能锁箱的无线控制器。

### 3.1 工作模式
ESP8266 同时运行两个服务：
- **Blinker 库**：连接手机 App（点灯科技平台），提供按钮、数值等组件
- **Web 服务器**：内嵌 HTML 页面（80 端口），浏览器可直接访问控制

### 3.2 控制逻辑
- 继电器接在 GPIO0 引脚
- `LOW`（低电平）= 打开设备（开锁）
- `HIGH`（高电平）= 关闭设备（关锁）
- HTTP 接口：`/on` 打开、`/off` 关闭、`/status` 查询状态

### 3.3 WiFi 配置
```cpp
char auth[] = "your_blinker_auth";  // Blinker 设备密钥
char ssid[] = "your_ssid";           // WiFi 名称
char pswd[] = "your_wifi_password";      // WiFi 密码
```

## 四、DHT11 温湿度传感器

### 4.1 基本参数
- 测温范围：0~50°C，精度 ±2°C
- 测湿范围：20%~90% RH，精度 ±5%
- 采样周期：≥1 秒
- 通信方式：**单总线协议**（一根数据线）

### 4.2 单总线协议流程
1. **主机发送起始信号**：拉低数据线 ≥18ms，再拉高 30μs
2. **DHT11 响应**：拉低 80μs → 拉高 80μs
3. **数据传输**：40 位数据（MSB 优先）
   - 8bit 湿度整数 + 8bit 湿度小数 + 8bit 温度整数 + 8bit 温度小数 + 8bit 校验和
4. **判断 0/1**：每位以 50μs 低电平开始，高电平持续 26~28μs 为 "0"，70μs 为 "1"

```c
// 核心读取代码（dht11.c）
DHT11_Mode_Out_PP();    // 主机设为输出
macDHT11_Dout_0;        // 拉低 → 起始信号
delay_ms(18);            // 保持 18ms
macDHT11_Dout_1;        // 拉高
DHT11_Mode_IPU();       // 切换为上拉输入，等待 DHT11 响应
// ... 读取 5 个字节 ...
```

### 4.3 校验和验证
```
校验和 = (湿度整数 + 湿度小数 + 温度整数 + 温度小数) & 0xFF
```

## 五、引脚连接关系总览

```
STM32F103ZET6
├── PA9  (TX1) ──── 调试串口（USB转TTL）
├── PA10 (RX1) ──── 调试串口
├── PA2  (TX2) ──── BC20 4G 模块 RXD
├── PA3  (RX2) ──── BC20 4G 模块 TXD
├── PA12 ────────── BC20 4G 模块 PWRKEY（开关机控制）
├── PA11 ────────── DHT11 DATA（数据线）
├── PB3  ────────── LED3
├── PB4  ────────── LED2
├── PB5  ────────── LED1
├── TX3  ────────── 树莓派 RXD
└── RX3  ────────── 树莓派 TXD

ESP8266（独立供电）
├── GPIO0 ───────── 继电器控制端
├── VCC ─────────── 3.3V
└── GND ─────────── GND
```

## 六、接线注意事项

1. **共地**：所有模块的 GND 必须连在一起（共地），否则信号不稳定
2. **4G 模块供电**：BC20 峰值电流可达 2A，需要独立供电或使用充足电源
3. **PA12 开机时序**：拉高 1 秒 → 拉低，模拟按下 PWRKEY 按键开机
4. **DHT11 上拉电阻**：数据线需要外接 4.7KΩ 上拉电阻（部分模块自带）
5. **ESP8266 独立运行**：ESP8266 通过 WiFi 控制锁箱，与 STM32 无直接连线，只需共地即可
